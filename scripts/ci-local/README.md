# ci-local

Reproduces the jobs of `.github/workflows/ci.yml` (format, lint, typecheck, test-lite, image, and the docker groups) as a recorded local run in clean environments. It is a fallback and a pre-push dry run for when hosted CI is unavailable, and spends nothing.

## Usage

```
scripts/ci-local/run.sh [--out <dir>] [--jobs format,lint,typecheck,test-lite,image,docker] [--keep] [--image-tag <tag>]
```

Only committed state (`HEAD`) is tested; the verdict header warns when the worktree is dirty. The selected jobs all start at once and run in parallel, as the `ci.yml` jobs do (a failing cheap job does not skip the Docker groups); `docker` runs after `image` (`ci.yml`: `needs: [image]`), and selecting `docker` selects `image` too. Each job's `secs` includes contention from the others on the same machine. Needs bash 4 or newer (macOS `/bin/bash` is 3.2: `brew install bash` and run `/opt/homebrew/bin/bash scripts/ci-local/run.sh`; older bash exits nonzero before any job starts), Docker, `git`, `python3`, `tar`, and for `image` and `docker` a host pnpm and a host Node of major 24 (the script refuses with `note=host-node-24-unavailable` otherwise). Exit 0 means every expected verdict line has `rc=0`: one per selected job, with `docker` expanded to one `docker-<group>` line per group; a missing line counts as failure.

Output in `--out` (default a fresh `/tmp/ci-local-out.*`): `verdict.txt` (read it whole), one `<job>.log` per job (`image.log`, and `docker-<group>.log` per group), and per group the test output `docker-<group>.pnpm.log`. Verdict lines look like `job=test-lite rc=0 secs=<n> log=... tests=N pass=N fail=N cancelled=N skipped=N todo=N`. Counts sum every node:test totals line (`ℹ tests N`, or `# tests N` for TAP) across the `pnpm -r` output after stripping ANSI colour; pnpm prefixes each line with `<package> test: `, so the match is anchored at the line end, not the start. Packages that spawn nested `node --test` runs may double count; treat counts as a signal and `rc` as the verdict.

## How each job runs

- format, lint, typecheck, test-lite: a fresh `node:24-bookworm-slim` container each, no Docker socket, no bind mounts. The repo goes in via `docker cp` as a fresh clone of `HEAD` (the same checkout as image and docker below: committed files and `.git`, no `node_modules`, no local state), because `actions/checkout` leaves a `.git` and the env-drift tests run `git ls-files`. The container runs with `--init`, so orphans are reaped as systemd reaps them on the hosted runner; without it `jobs.test.ts`'s killed grandchildren stay zombies and look alive. Inside, as root: `apt-get install git python3 ca-certificates procps` (checkout and real-git tests, the floor step, https registry, `ps`), `corepack enable` (pnpm comes from `package.json` `packageManager`). Then everything runs as non-root user `runner` (uid 1001): `pnpm install --frozen-lockfile`, then the job command; test-lite first runs the git floor step. Per-step and per-job timeouts mirror `timeout-minutes`; container setup counts toward the job time.
- image and docker: on the host with the host's own `node` (major 24, the same as the container jobs; the run log records `::host-node`), because the Docker-gated suites bind-mount host temp paths and that cannot work from a container. The checkout is `git clone --no-local` of the repo's object store, detached at `HEAD`, origin removed, under `/tmp`. A bare `git archive` has no `.git`, which breaks the image build (`git rev-parse --short HEAD` stamps the revision label) and `docker-gate.ts` (`git rev-parse`/`git diff` against `PTREE_AGENT_TEST_REVISION`); a clone keeps the real sha and contains only committed files. image: install, then `AGENT_IMAGE_TAG=<tag> pnpm --filter @pomtree/agent-image build:image`. docker: for each group in `scripts/ci/docker-groups.json`, in order, the floor step, `pnpm test:docker:<group> 2>&1 | tee test-docker.log` (exit status taken from `PIPESTATUS[0]`), the group's skip guard (also after failed tests, as in `ci.yml`), and on failure the diagnostics commands. A failing group does not stop the next one (`ci.yml`: `fail-fast: false`).

The git floor step's python is extracted from `ci.yml` at run time, not copied, and the skip guard is the same checked-in `scripts/ci/skip-guard.py` that `ci.yml` runs. A drift guard aborts if a mirrored `ci.yml` line is missing or the floor step differs between jobs; update `run.sh` when it fires.

## Differences from hosted CI

- Image tag: `pomtree/agent:ci-local-<shortsha>` (override with `--image-tag`), not `pomtree/agent:dev`; the host's existing `:dev` image is never overwritten, and the script refuses `:dev` or any tag that already exists. It removes the image at the end unless `--keep`.
- Groups run one after another on one Docker daemon. In `ci.yml` each group is a matrix entry on its own VM with its own daemon, so the groups cannot contend for ports, networks or CPU; here they share the host daemon, so they run in sequence rather than in parallel, and their wall time adds up. The image is built straight into that daemon: `ci.yml`'s `docker save | zstd` into actions/cache, restore and `docker load` are not reproduced, nor its `cleanup` job that deletes that cache entry; ci-local removes the image itself on exit.
- No TAP artifact: `ci.yml` sets `E2E_TAP` so the e2e group scripts also write a TAP stream it uploads; ci-local leaves it unset (the scripts then write it to `/dev/null`) and keeps only the spec output in `docker-<group>.pnpm.log`.
- Extra env on the docker groups: `PTREE_AGENT_TEST_IMAGE=<tag>`. `ci.yml` relies on the sandbox-docker gates defaulting to `:dev` (`docker-gate.ts` `IMAGE`); with another tag they must be told. `PTREE_AGENT_TEST_REVISION` is the full `HEAD` sha, as `github.sha`.
- Not reproducible: `actions/checkout`, `pnpm/action-setup` and `actions/setup-node` (pnpm cache) are replaced by the clone, corepack and the node image; the host runs image and docker, so its Docker version, kernel, firewall and installed pnpm and git differ from a fresh ubuntu-26.04 VM and carry local state (other containers and networks); `concurrency` cancellation, `permissions`, and the PR/push triggers do not apply; the container jobs get Debian bookworm's git 2.39 rather than ubuntu's newer git.
- `CI=true` is set for all jobs, as on hosted runners.
- Test user: `ci.yml` creates (or reuses) a uid-1000 account in the docker group and runs `pnpm test:docker:<group>` as it via `sudo` in each `docker` entry, because the hosted runner user is uid 1001 and pomtreed must run as uid 1000 (`deploy/INSTALL.md`). ci-local runs the docker groups as the invoking user with no `sudo`, so on a host whose user is not uid 1000 the agent-container tests fail the same way they did on the hosted runner.
- Docker in the lite jobs: a hosted ubuntu-26.04 runner has Docker installed even for the jobs that do not use it; the lite containers here have none by design. This does not leave a gap: the hermetic lite preflight in `examples/hn-digest/content-live-runtime.test.mts` runs without Docker, because its tests pass a stand-in `bridgeGateway` (`TEST_BRIDGE_GATEWAY`) to `openLiveContentRuntime`, so the runtime never asks Docker, and `detectBridgeGateway` in `packages/pomtreed/src/agent-net.ts` turns both a missing `docker` binary and a nonzero exit into `undefined`.
- Parallel jobs share one machine; a hosted runner gives each job its own small VM, so local per-job seconds are not comparable with hosted ones.
- Concurrency: `ci.yml` sets `E2E_TEST_CONCURRENCY=2` and `WORKSPACE_TEST_CONCURRENCY=2` (test-lite and docker) for the small hosted runner; ci-local leaves both unset, so the e2e groups and the root lite script use their own higher defaults on this machine.
- Container setup (apt, corepack, install) is repeated by every container job. A prebuilt base image would be faster but would hide a failure in the apt or corepack setup that hosted CI also performs, so there is none.

## Options

`--keep` keeps the work directory and the built image (containers are created with `--rm` and always vanish on exit). Without it everything the script created is removed on exit.
